# Exam Generator & Corrector

A no-login web app that generates OMR-scannable math exams (weighted by
grade/area) and grades photographed answer sheets automatically, plus a
companion Android app for grading from a phone camera.

## What's in here

- `backend/` - Flask web app: Exam Generator + Exam Corrector, question
  bank, PDF rendering, and the OMR grading engine. This is the actual
  app; it needs a real Python host (Render, below), not GitHub Pages.
- `mobile/` - Flutter app source (`lib/main.dart` + `pubspec.yaml`). The
  `android/`/`ios/` platform folders are generated by CI, not checked in.
- `site/` - a static landing page (links to the live app + the APK)
  deployed to GitHub Pages. GitHub Pages only serves static files, so it
  cannot run the Flask backend itself -- that's why the backend is
  deployed separately, to Render, per the one-time setup below.
- `render.yaml` - Render Blueprint describing the backend as a free web
  service (gunicorn).
- `.github/workflows/build-apk.yml` - builds the Android APK on every push
  to `mobile/` and publishes it to the repo's "latest" GitHub Release.
- `.github/workflows/deploy-backend.yml` - pings a Render deploy hook
  whenever `backend/` changes, so the live app stays up to date.
- `.github/workflows/deploy-pages.yml` - publishes `site/` to GitHub
  Pages whenever it changes.

## Deployment (one-time setup)

After this, every push auto-deploys; these three steps only need doing once.

1. **Backend -> Render.** On [render.com](https://render.com), click
   **New +** -> **Blueprint**, connect this GitHub repo (Render reads
   `render.yaml` automatically), and deploy. Render assigns a URL --
   normally `https://exam-corrector.onrender.com`. If yours differs, update
   `APP_URL` in `site/index.html`.
   - Then, on that service's page in Render: **Settings** -> **Deploy Hook**
     -> copy the URL -> add it to this repo as a secret named
     `RENDER_DEPLOY_HOOK_URL` (**Settings** -> **Secrets and variables** ->
     **Actions** -> **New repository secret**). This lets
     `deploy-backend.yml` redeploy automatically on every push.
2. **GitHub Pages.** In this repo's **Settings** -> **Pages**, set
   **Source** to **GitHub Actions**. `deploy-pages.yml` then publishes
   `site/index.html` on every push.
3. **APK releases.** Nothing to configure -- `build-apk.yml` already
   publishes to this repo's own GitHub Releases using the built-in
   `GITHUB_TOKEN`.

### Known limitation: exam/result storage on Render's free tier

The backend currently stores generated exams and corrected results as
local JSON files (`backend/data/exams/`, `backend/data/results/`).
Render's free web services have **ephemeral disk** -- that data is wiped
on every redeploy and can be lost if the service restarts after spinning
down from inactivity. This is fine for trying the app out, but for real
classroom use you'd want to point it at a persistent store (a Render
paid disk, or an external database) before relying on it long-term.

## Scope

Only Cycle 2 (General track: G5-G8) and Cycle 3 (Advanced + General
tracks: G9-G12) are supported, per the school's math-area weighting
table. Cycle 1 and every Applied/Elective track are intentionally out of
scope. The question bank has 20 questions per math area per cycle (240
total), auto-generated with parametrized templates so every exam draws a
fresh, non-repeating set.

## Running the backend

```bash
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python3 question_bank_gen.py   # only needed once, to (re)build data/question_bank.json
python3 app.py                 # serves http://localhost:5000
```

Open `http://localhost:5000` for the Exam Generator, `/corrector` for the
Exam Corrector. No login, no external services required.

### How grading works

Every generated exam records the exact printed position of each answer
bubble (`exam_pdf.py`). To grade a photo of a completed sheet,
`omr_corrector.py` detects the 4 black corner squares printed on the
page, computes a perspective transform back to that exact layout, then
samples darkness at each known bubble position -- rather than guessing
with generic circle detection. This is robust to a sheet photographed at
an angle, rotated, or slightly skewed, as long as all 4 corners are
visible.

## Mobile app

The Flutter app lets a teacher pick a previously generated exam, photograph
each page of a student's sheet, and get the same grading result as the
web app. It only ships `lib/` and `pubspec.yaml`; CI runs `flutter create`
to regenerate the Android project scaffold before building, so there's
nothing else to set up locally beyond having Flutter installed if you
want to run it yourself:

```bash
cd mobile
flutter create --platforms=android .
flutter pub get
flutter run
```

The APK is built automatically by GitHub Actions and published to this
repo's "latest" release; the web app's "Download App (APK)" button links
directly to that release asset.
